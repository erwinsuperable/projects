02 — Challenges

Seven ways fragmentation compounds.

Design teams have worked across brands and squads in silos — solving the same problems repeatedly, with no shared reference point.

01

Designers work in silos

Buttons, cards, nav, checkout — the same components look and behave differently across brand teams.

02

No source of truth

No central place shows the latest approved component, its variants, owner, or lifecycle status.

03

Unclear ownership

No defined system owner or contribution model — local needs quietly become permanent variants.

04

Design ≠ production

Figma and coded components evolve separately, creating QA gaps and lower design-to-code confidence.

05

Variations accumulate

New requirements spawn new variants with no framework to decide: shared, themed, or true exception.

06

CMS disconnected

Content modules built apart from components become either too rigid, or too open to misuse.

07

Edge cases, repeated

RTL, Arabic, accessibility and empty/error states get solved per-project instead of built once — quality depends on which squad happened to touch it.

03 — Lessons

04 — Solution

One layered architecture, built alongside FACES.

Structure and behavior stay shared. Brand difference comes only through tokens, configuration, content and approved composition.

Brand ThemesColor, type, imagery, density, visual expression — per brand
Page LayoutsApproved compositions — home, PLP, PDP, cart, checkout, account
CMS ModulesEditor-configurable heroes, banners, carousels, category grids
UX PatternsSearch, discovery, auth, cart, checkout, error recovery
Core UI ComponentsButtons, inputs, cards, nav, dialogs, tabs, feedback
FoundationsTokens, grid, spacing, type roles, radius, elevation, motion

Map broadly. Build deliberately. Only validated, near-term needs get built during the pilot.
