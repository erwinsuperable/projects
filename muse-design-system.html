The complete token and component language for the MUSE loyalty experience across App, Web, and mConnect. Getting started

Two files ship with this site: muse-tokens.css (drop-in CSS custom properties, three layers: base ramps → semantic aliases → scales) and muse-tokens.json (W3C Design Tokens format for Style Dictionary, Tokens Studio, or any token pipeline). Bind product code to the semantic layer only — raw ramp steps are an implementation detail of the theme.

Accessibility contract. Native <button> only. Disabled buttons keep their label; a validating button also sets aria-busy="true" and disabled so it cannot be double-submitted. Focus ring: 2px LoyaltyBlue500 with 2px offset on :focus-visible.

Platform: Liquid Glass

  • MUSE has adopted iOS 26 Liquid Glass; the liquid button type implements the translucency + reflective gradient per Apple's Adopting Liquid Glass guide.
  • On older iOS and Android, use a frosted button treatment to mirror the effect.
  • Validation flow: pressed → inline loading (“Please wait…”) → success or error resolution.

Documented compositions & states

  • States: default, hover, active, filled (input-stroke-filled), error, disabled, read-only (“This text is for viewing only.”).
  • Search type adds a persistent clear control; phone type composes a fixed dialing prefix (+971) before the input.
  • A dropdown trigger variant exists: label + chevron opening an option list (modal or bottom sheet — see Action menu).
  • Inline validation messages sit directly beneath the field and update dynamically as the user types.

When to use

  • To organize related information.
  • To shorten pages and reduce scrolling when content is not crucial to read in full.
  • When space is at a premium — mobile interfaces, side panels.

When not to use

  • If a user is likely to read all of the content, don't add the extra click — use a full scrolling page with normal headers.

Anatomy

  • Header title — the section title, and the control that reveals the panel.
  • Chevron — indicates open/closed state.
  • Panel — the content associated with the header.

Action menu

A list of choices opened from a trigger. Two presentations, chosen by content weight.

Choosing the trigger

  • Modal — for smaller lists or light content that doesn't need the full screen.
  • Bottom sheet — for large or complex content requiring full-screen coverage; dismissed by dragging the sheet downward.

Anatomy

  • Trigger row: label + chevron (action-menu-trigger, default / selected states).
  • Items in radio style (single choice) or menu style (navigation); optional leading icon and search.
  • Country switcher variants exist for app and web, in normal and liquid styles, light and dark modes.
Code
HTML
<button class="list-tab" aria-haspopup="dialog" aria-expanded="false">
  <span class="t"><b>Country</b><span>United Arab Emirates</span></span>
</button>
<dialog class="sheet"><!-- action-menu-list: search + radio items --></dialog>

Accessibility contract. Critical and warning alerts use role="alert" (interrupts); snackbars and success confirmations use role="status" (polite). A snackbar with an action must persist long enough to reach by keyboard — the documented duration is 5 seconds, and it should pause on hover/focus.

Snackbar (modal type)

  • Appears at the bottom; auto-dismisses after 5 seconds with an ease-out animation.
  • Users can also dismiss via the ✕ or by swiping left; with an action button it persists until dismissed or actioned.
  • Three layouts: single line + close · double line + close · long line + action link + close.

Non-modal banner

  • Appears at the top of the content and informs without blocking interaction — passive, auto-dismissing or persistent without required action.

Inline message

  • A single contextual line beneath a field or component, changing dynamically with user actions (validation feedback).

Aspect ratio

A utility that keeps media proportional across devices — 1:1, 4:3, 16:9, 5:4, 3:2, 2:1, 21:9, each in landscape or portrait, with an optional 50%-height mode.

When to use

  • Media-driven components: images, video, banners, cards.
  • When visual hierarchy and composition must hold across breakpoints.
  • When a child element must scale responsively while preserving proportion.
  • Reusable components shared between mobile and web.

When not to use

  • Purely text-based containers where height should be dictated by content.

Fit modes

  • Filled — the image fully covers the container.
  • Fitted — centered, not filling the container; typically for brand logos.
Code
CSS
.media-16x9 { aspect-ratio: 16 / 9; }
.media-16x9 img.filled { width: 100%; height: 100%; object-fit: cover; }   /* Filled */
.media-16x9 img.fitted { width: 100%; height: 100%; object-fit: contain; } /* Fitted (logos) */

Shared specs (from the source docs)

  • Corner radius radius-xl (24px) · elevation shadow-md · section background configurable.
  • Press transition is identical to the Apple App Store card effect.
  • Media fit modes: Filled — image covers the container; Fitted — centered without filling (brand logos).

Content rules

  • Card A: title title-sm ≤14 chars · subcopy parag-md ≤20 · banner tag small · image 1:1 default.
  • Card B: 4:3 media + configurable gradient · kicker label-md-strong ≤32 · title subheading-lg · description ≤112 · contrast button.
  • Card C: 1:1 image with 40% black overlay · label label-md-strong ≤14.
  • Card E: title subheading-sm ≤25 · subcopy parag-sm ≤38 · badge caption-md ≤14.
  • Banner tag large: ≤80 characters including spaces.

Bottom nav — SF Symbol mapping

  • house.fill Home — main page, modules & personalized content.
  • tag.fill Offers — promotions, discounts, available offers.
  • Center: QR symbol that animates into the “M” logo — opens the MUSE ID to earn/burn points at checkout.
  • heart.fill Brands · calendar.badge Experiences · ellipsis More (Gift card, Tier benefits…).

Behavior rules

  • Persistent across all main sections; every tap target ≥ 48×48dp.
  • Re-tapping the current tab reloads the section or scrolls back to top.

Header behavior

  • Homepage: tier color treatment communicates loyalty status; points animate into view on entry; account icon opens the Dashboard with animated transitions.
  • On scroll the header becomes a compact rounded variant; Account/Chat turn into sticky liquid-glass buttons; the compact header acts as back-to-top.
  • Inner pages (e.g. Brands) use the distinct MUSE red header; on scroll the title fades, filters hide (returning at top), and the red transitions to a soft iOS-style adaptive gradient.
